# 티켓 설정 화면 (DANZ-368)

## 관리자 흐름

1. `/admin`에서 축제 이름과 운영 기간을 저장한다. 운영 날짜가 부스맵·타임테이블의 날짜 목록 및 티켓 공연일 선택지로 쓰인다.
2. 상단 티켓팅 → **티켓 설정**(`/admin/ticketing`)으로 이동한다. 축제 설정과 같은 회차 ID/API를 사용한다.
3. 수정 → 회차별 예매 시작 시각·수량·공연일 선택 → 저장. 축제 3일 중 2일에만 회차를 만들어도 된다.
4. 새 회차는 세 값을 입력하고 **회차 추가**한 뒤 상단 **저장**으로 반영한다. 작성 중인 입력란을 남겨두면 추가하거나 닫으라는 안내가 나온다.
5. ON/OFF는 조회 상태에서도 클릭 가능하며 편집 상태로 전환된다. **상단 저장까지 해야 실제 반영**된다. 취소하면 서버의 마지막 저장값을 다시 읽는다.
6. 시작된 회차는 시각·수량·공연일 수정이 잠긴다. 변경하지 않은 잠긴 회차를 포함해 다른 설정은 저장할 수 있다. 삭제는 별도 정책이며 이미 발급된 티켓이 있으면 취소 대상 수량을 확인받는다.
7. **팔찌 배부 ↗**는 같은 창에서 `/ticket/admin`으로 이동한다. 기존 인증·권한에 따라 배부 화면으로 연결된다.

## 관리자 설정이 반영되는 곳

| 항목 | 사용자 예매 목록 | 팔찌 배부 목록 |
| --- | --- | --- |
| 제목 | 축제 이름 + DAY n | 축제 이름 + DAY n |
| DAY 계산 | 공연일이 축제 시작일에서 몇 번째 날인지 계산 | 동일 |
| 예매 시작 일시 | 두 번째 줄에 날짜·요일·시각, 한국 시간 | 별도 항목, 한국 시간 |
| 공연일 / 수량 | 카드의 추가 줄에서 제외 | 운영 정보로 표시 |
| 조회 대상 | 설정 회차에 연결된 이벤트만 | 동일 |

같은 탭은 저장 직후 상태를 갱신하고, 다른 탭은 포커스 복귀 또는 최대 30초 주기 조회로 반영한다.

## OFF 정책과 두 가지 배경

OFF는 신규 예매만 막는다. 로그인(`/ticket/login`), 회원가입(`/ticket/signup`), 내정보(`/mypage`), 기존 내 티켓(`/ticket/my-ticket`)은 유지한다. 회차·발급 티켓은 삭제하지 않는다.

- **OFF 안내 배경**: `ticketingBackgroundImageUrl`. OFF 설정 영역에서 변경한다. null이면 기존 LEGEND 입장 안내를 보여준다.
- **발급 티켓 카드 배경**: `ticketCardBackgroundImageUrl`. ON 설정 영역에서 변경한다. 예매 완료 후 내 티켓 카드에만 적용하며, 티켓팅 페이지 전체 배경은 기존 디자인을 유지한다. OFF로 전환해도 저장된 카드 배경은 보존한다.
- JPG/PNG 선택 → 저장 전 미리보기 → 상단 저장 시 업로드 및 URL 저장. 기본 배경 버튼도 상단 저장이 필요하며 취소하면 되돌린다.
- 기본 카드 이미지는 `public/posters/ticket-card-legend-light.jpg`다. 제목·DAY·공연일·배부 시간·순번은 `var(--accent)`를 사용하고 상태 배지는 상태별 색상을 유지한다.
- 관리자와 사용자 카드는 공용 `PaperTicketCard`를 쓴다. 관리자 미리보기의 **5/13·NO.2094는 예시 값**이다. 실제 내 티켓은 API의 공연일·예매 순번을 표시한다.
- 팔찌 배부 시간 **10:00~는 현재 고정 표시**이며 이번 설정에서 수정할 수 없다.

## 비동기 예매 응답

PROCESSING 응답은 1초 간격, 최대 30회 결과 조회 후 성공/실패를 판별한다. 결과가 불확실한 상태에서 예매 요청을 자동 재전송하지 않는다. 처리 지연과 입장 자격 만료(`RESERVE_ADMISSION_EXPIRED`)를 구분하여 안내하고 목록 복귀·재진입을 유도한다. 일반 서버 오류를 매진·중복 예매로 단정하지 않는다.
