# 홈 이미지 편집 동작 (2026-10-14)

## 변경 내용

- 축제 설정의 홈 배너 요약과 관리 목록을 세로 9:16 미리보기로 변경했다. 이미지는 `object-contain`으로 전체를 표시한다.
- 테마 화면을 `홈화면 이미지 파일 선택` 또는 `공식 포스터로 편집` → 미리보기 → `홈화면 이미지 저장` / `이미지 선택 취소` 흐름으로 정리했다. 저장·취소는 선택/편집을 시작한 뒤 미리보기 아래에 나타난다. 취소는 초안을 버리고 기존 저장 이미지를 유지한다.
- `공식 포스터로 편집`은 편집 설정만 연다. `원본 비율 유지` / `세로 화면에 맞춰 자르기`를 선택하고 `편집 결과 미리보기`를 누르면 초안을 생성한다. 아직 저장하지 않으며, 파일 선택과 동일한 저장 버튼으로 반영한다.
- 단독 저장은 축제 운영(OPERATIONS) 권한으로 사용할 수 있다. AI 추천이나 티켓팅 권한이 필요하지 않으며, 색상 테마·티켓 배경·나머지 홈 이미지 및 순서를 변경하지 않는다.
- 포스터 전체 보기(contain)는 원본 비율을 유지한 이미지로 만든다. 서버가 고정 캔버스에 흐린 여백을 합성하던 처리와 실제 홈/테마 미리보기의 흐린 복제 배경을 제거했다. 화면 채우기(cover)의 9:16 자르기와 초점 조정은 유지한다.
- 실제 홈과 테마 화면 미리보기는 5월 운영 당시처럼 이미지로 영역 전체를 채운다(`object-cover`, 중앙 기준). 화면과 이미지 비율이 다르면 가장자리가 잘릴 수 있다. 편집의 `원본 비율 유지`는 저장 파일을 만드는 방식이며, 홈 화면에서 전체 이미지를 보장하는 옵션은 아니다. 원본 파일에 이미 들어 있는 여백이나 과거에 저장한 합성 여백은 자동으로 제거하지 않는다.

## 저장 경로와 실패 처리

1. JPG·PNG 파일의 크기(5MB), 시그니처, 디코딩 및 픽셀 수를 검사한다.
2. 기존 `POST /admin/festival/{id}/home-images/staged`로 파일을 준비한다. 동일 초안의 실패 후 재시도에서는 업로드 결과를 재사용한다.
3. `PUT /admin/festival/{id}/home-images/first`에 imageUrl, expectedFirstImageId, expectedFirstImageUrl, sourcePosterUrl을 보낸다. 직접 선택한 파일의 sourcePosterUrl은 null이다.
4. 서버가 해당 축제의 홈 이미지인지 검사하고, 잠금 아래 첫 이미지와 포스터의 현재 상태를 비교한다. 기존 첫 이미지의 ID·순서는 유지하고 URL만 교체한다. 빈 목록이면 첫 이미지를 만든다.
5. 성공하면 초안을 해제하고 새 첫 이미지 정보를 기준으로 갱신한다. 공개 홈 이미지 쿼리 캐시도 무효화한다. 테마 전체 적용은 홈 이미지 초안과 무관하게 색상·티켓 배경만 저장한다. 홈 이미지 목록 조회 실패나 미저장 초안은 테마 적용을 막지 않으며, 테마 적용 후에도 초안은 그대로 유지한다. 테마 화면 미리보기에는 미저장 초안 대신 현재 저장된 홈 이미지를 표시한다.
6. 저장 중 버튼을 잠가 중복 요청을 막는다. 일반 실패는 초안을 유지한다. 409 충돌 시 `최신 홈 이미지 확인`으로 첫 이미지 상태를 다시 읽고, 사용자가 다시 저장해야 한다. 공식 포스터 자체가 바뀌었다면 페이지를 새로고침하고 미리보기도 다시 만든다.

업로드가 성공한 뒤 저장에 실패하면 파일은 저장소에 남고, 재시도할 때 재사용한다. 이후 사용자가 초안을 취소하거나 페이지를 떠난 경우의 임시 파일 자동 정리는 기존 전체 적용 경로와 마찬가지로 별도 과제다. 현재 구현은 기존 파일을 자동 삭제하지 않는다.

## 확정한 버튼과 역할

| 버튼 | 동작 |
| --- | --- |
| 홈화면 이미지 파일 선택 | 기기 파일을 읽어 미리보기. 아직 업로드/저장하지 않음 |
| 공식 포스터로 편집 | 포스터 배치·초점 편집 영역을 열기 |
| 편집 결과 미리보기 | 현재 배치 설정으로 이미지 초안 생성 |
| 홈화면 이미지 저장 | 현재 초안을 첫 홈 이미지로 저장 |
| 이미지 선택 취소 | 초안을 취소하고 기존 홈 이미지로 돌아가기 |

저장과 취소는 파일 선택 버튼보다 뒤, 미리보기 아래에 둔다. 취소 안내는 `취소하면 기존 홈화면 이미지를 유지합니다.`로 표시한다. 선택된 파일명 또는 `공식 포스터 편집 결과`와 `저장 전` 상태를 미리보기 아래에 표시한다.

별도 테마 선택 화면은 [테마 선택 화면](theme-selection.md)을 참고한다. 기존 제작 화면 하단 목록도 유지한다.

## 검증 및 배포 상태

FE 테스트는 단독 저장, 실패 시 초안 보존·업로드 재사용, 중복 클릭 방지, 충돌 후 첫 이미지 재확인, 운영 권한만 있는 계정, 테마/티켓 배경 미변경을 다룬다. 세로 미리보기와 흐린 복제 이미지 제거도 회귀 검사한다.

2026-10-14 로컬 검증: 관련 6개 테스트 파일의 113개 테스트 통과. `npm run build`(앱 타입 검사 포함), `npm run typecheck:test`, 변경 파일 ESLint, `git diff --check` 통과. 테마 선택 화면의 기본·저장 테마 적용과 메뉴 이동, 전체 적용 시 홈 이미지 초안 보존, 저장된 홈 이미지로 화면 미리보기도 포함한다.

2026-10-14 `20261014-home-theme` 배포로 단독 저장 API와 FE를 Azure에 함께 반영했다. 기존 BE `0273507`, FE `b8a2a65d`에 이번 미커밋 변경을 더한 소스이며, 정확한 파일 해시는 서버 복구 디렉터리의 `patch-manifest.json`과 `local-manifest.json`에 기록했다.

HTTPS 및 실제 관리자 브라우저에서 새 버튼, 편집 영역의 저장·취소, `/admin/theme/select`의 목록·미리보기 표시를 확인했다. 편집 영역 열기·취소만 수행했고 실제 업로드·저장·테마 적용은 호출하지 않았다. 기존 콘텐츠 20개 테이블의 데이터 해시, MySQL·Redis·Kafka 컨테이너 ID, Compose·비공개 환경 파일 해시가 배포 전후 일치했다. Blob 쓰기·삭제와 DB 스키마 변경은 수행하지 않았다. 커밋·푸시는 아직 실행하지 않았다.

BE 검증과 API 명세는 BE `docs/home-image-save.md`, 배포·복구 기록은 BE `docs/azure-vm-deployment.md`의 `홈 이미지 단독 저장·테마 선택 화면 배포` 절을 참고한다.

## 후속 변경: 5월 홈 표시 방식 복원 (2026-10-14 Azure 배포)
