# 테마 제작 색상 규칙 (2026-10-14)

새 테마, 복제본, AI 추천 시안과 수정 저장은 아래 규칙을 사용한다. 메인 색상은 추출한 기준색 자체가 아니라 최종 테마의 `brand.primary`를 뜻한다. AI는 브랜드 4색을 추천하고, 의미가 고정된 상태·지도 색상은 테마 분위기로 바꾸지 않는다.

| --- | --- |
| 주점 | 최종 Primary와 동일 |
| 푸드트럭 | `#ec4899` |
| 부스 | `#10b981` |
| 이벤트 | `#f6ca3b` |

| 편의시설 | `#3b82f6` |

고정값은 기존 `src/index.css` Theme Core 기본값이다. 다른 색상 표준을 새로 도입하지 않았다. Primary가 다른 지도 카테고리와 같더라도 주점 색상을 강제로 보정하지 않는다.

## 화면과 저장

- 브랜드 4색만 편집할 수 있다. 상태·지도 색상은 읽기 전용이며 Primary를 수정하면 주점도 바로 바뀐다.
- 새 테마·복제·AI 후보 미리보기·저장·전체 적용에 같은 규칙을 적용한다. 백엔드에서도 저장 및 추천 경로를 정규화한다.
- Coastal Sunset은 5월 브랜드 색상을 유지하고 상태·지도 색상에는 공통 규칙을 사용한다. 예전 색상으로 저장된 복사본은 기존 저장 테마로 남는다.
- 기존 저장 테마를 조회하거나 선택·활성화할 때는 데이터를 자동 변경하지 않는다. 수정하거나 복제해 저장할 때 새 규칙이 적용된다. 활성 테마 수정본은 기존 흐름대로 별도 비활성 테마로 저장하고, 적용은 별도로 한다.
- 홈 이미지, 포스터, 게시물, 티켓 배경은 이 변경에 포함하지 않는다.

## 검증 상태

2026-10-14 `20261014-theme-policy`로 BE·FE를 Azure에 배포했다. 실제 관리자 화면에서 새 테마 초안의 고정값과 Primary 변경 시 주점 색상 연동을 확인하고 저장 없이 새로고침해 초안을 버렸다. 기존 활성 테마는 유지했다. 관련 테스트는 고정값, 주점 연동, 기존 객체 보존, AI 전체 적용과 편집·저장 흐름을 확인한다. 실제 AI API 호출은 수행하지 않았다.

FE 검증: 관련 2개 파일 69개 테스트, 프로덕션 빌드, 테스트 타입 검사, 변경 파일 ESLint 및 `git diff --check` 통과.

VM의 BE·FE Docker 빌드, 앱 health, 주요 HTTPS 경로가 정상이다. 배포 전후 및 브라우저 검증 후 20개 콘텐츠 테이블의 데이터 해시가 일치했다. 복구 자료는 VM `/opt/danzzan/deployment-backups/20261014-theme-policy/`에 보관한다.

커밋 분리 검증: 이전 홈 이미지 단독 저장·테마 선택 기능을 제외한 스테이징 소스를 별도 임시 디렉터리에서 검사했다. 색상 정책·관리자 테마·홈 캐러셀 71개 테스트와 앱 타입 검사를 통과했다. 기존 작업 트리 파일은 덮어쓰지 않았다.
